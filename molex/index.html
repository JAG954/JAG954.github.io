Professional Case Study · June-July 2026

Global ERP Testing Orchestration

Centralizing a distributed ERP smoke testing and UAT program into one traceable, automation-supported operating system.

During a two-month contract through Actalent, I supported Molex Connected Enterprise Solutions as a Junior Project Manager. My work focused on the execution layer: turning thousands of test steps, dozens of scenarios, and four global teams into a shared workflow that could run continuously across time zones.

Problem, Task, Solution

Four operating problems solved during ERP readiness testing.

The value of the work came from connecting process design, workbook automation, tester usability, and live program coordination. Each problem had a practical operating task behind it, not just a reporting need.

Problem 01

Fragmented global coordination

Problem
Testing ownership, status, support resources, and escalation paths were distributed across teams and time zones.
Task
Centralize smoke testing and UAT coordination across four global teams while supporting a 24/7 follow-the-sun process.
Solution
Built a command-center workflow that connected schedules, task lists, issue logs, meeting links, support links, and progress views.

Problem 02

Tester work queues were hard to keep current

Problem
Thousands of test steps across dozens of scenarios made it difficult for each tester to find the next actionable item.
Task
Convert scenario-level testing data into current, owner-specific task lists without manual filtering.
Solution
Used Excel, Power Query, and Office Scripts to consolidate test steps and generate tester-specific task views.

Problem 03

Go-live blockers needed visible ownership

Problem
Active issues could slow readiness if assigned fixes, retesting status, and escalation ownership were not visible.
Task
Create a tracker that connected blockers, fixes, retesting, and resolution status for testers and leadership.
Solution
Created incident and issue-log workflows and supported bridge-line execution by monitoring activity and escalating blockers.

Problem 04

Leadership needed status without workbook friction

Problem
Senior stakeholders needed progress, blocker, and scenario context without digging through raw workbook tabs.
Task
Make the testing workspace easier to navigate and pair current data with repeatable program updates.
Solution
Designed user-centered dashboards with program leadership and developed Copilot agents for daily updates and Excel workflow debugging.

The System

A lightweight orchestration layer built around testers.

I designed the workflow around a simple principle: testers should update the work once, and the system should handle consolidation, status logic, reporting, and handoffs. The interface prioritized clear navigation while the automation worked behind the scenes.

Interface Design

A navigation system built for fast execution.

The visual design gave testers direct routes to their schedule, current task list, issues log, meeting links, learning items, and production environment. Scenario navigation and color-coded task assignment made a large testing program easier to scan and operate under time pressure.

Screenshots are tightly scoped to interface design and workflow structure. No personal data, incident descriptions, defect narratives, or detailed test instructions are shown.

Execution

The operating model mattered as much as the workbook.

  1. Standardize

    Create a shared definition of progress

    Aligned scenario data, ownership, and status fields so distributed teams could be compared without losing context.

  2. Enable

    Support testers in the workflow

    Created user-centered navigation and responded to tester questions so the system fit the work instead of adding reporting burden.

  3. Operate

    Run follow-the-sun handoffs

    Coordinated daily progress across global teams and maintained continuity as testing moved between time zones.

  4. Resolve

    Turn blockers into owned actions

    Worked through issue status, ownership, fixes, and retesting so active blockers stayed visible until resolution.

  5. Communicate

    Translate test activity into program updates

    Automated refreshes, script execution, and Outlook communications while using Copilot to draft daily status updates from current testing data.

Outcomes

A more coherent, usable testing operation.

One operating view

Distributed scenario data became a consolidated program view with visible ownership and status.

Less manual reporting work

Scheduled refreshes, script execution, and Outlook workflows reduced repeated status consolidation.

Faster handoffs

A shared workflow helped teams continue testing across time zones without rebuilding context.

Usability as a control

Clear navigation, current task lists, and tester support improved the quality and timeliness of status information.

What this experience demonstrates

I can enter a time-sensitive enterprise program, understand how people and data move through the process, build a practical technical system, and support adoption across multiple stakeholder groups. The value was not a single dashboard or script; it was the integrated operating workflow.
